# PlotWise AI

**AI-Based Real Estate Investment Decision Support System for Indian Cities**

PlotWise AI is a full-stack MERN application that helps users explore where Indian cities are
growing, using infrastructure development, government future plans, connectivity, and economic
activity signals. It is a **decision-support tool, not a financial advisor** — it explains *why*
an area receives a score and leaves the decision to the user.

> Scores are analytical estimates based on available data. They are not a guarantee of investment
> returns and are not financial, legal, or investment advice.

## Features

- 🔍 **City search** with autocomplete, popular cities, and recent searches (no login required)
- 📊 **City dashboard** with an overall growth score and per-factor breakdowns
- 🏆 **Ranked areas** within each city, each with growth drivers and risks
- 🧮 **Deterministic investment scoring engine** — the score is *never* generated by AI
- 🤖 **AI explanations** (Gemini) that interpret the score using only structured data, with a safe
  offline template fallback if no API key is configured
- 🏗 **Infrastructure explorer** by category (metro, highway, railway, airport, industrial, IT
  parks/SEZ, townships) with sources and "last verified" transparency
- 🗺 **Interactive map** (Leaflet + OpenStreetMap) with category-coded markers
- 📈 **Area detail page** with radar/bar charts, a growth timeline, and a "Why this score?" modal
- ⚖️ **Compare up to 3 areas** side by side, with an AI-generated comparison summary
- 🔖 **Local "Saved Analysis"** and recent searches via `localStorage` — no account needed
- 📱 Fully responsive (1440 / 1024 / 768 / 390px)
- 🔐 Backend-only AI calls, rate-limited, with Helmet/CORS/sanitization hardening

## Tech stack

**Frontend:** React 18, Vite, Tailwind CSS, React Router, Axios, Recharts, React-Leaflet,
Lucide React, Framer Motion

**Backend:** Node.js, Express.js, MongoDB, Mongoose

**AI:** Google Gemini API (`gemini-1.5-flash`), behind a swappable service layer
(`server/src/services/gemini.service.js`)

## Architecture

```
User → CitySearch → GET /api/cities/search
                        │
                        ▼
              City Dashboard (GET /api/cities/:slug)
                        │
        ┌───────────────┼────────────────────┐
        ▼                                     ▼
Top Areas (deterministic score          Infrastructure Projects
via investmentScore.service.js)         (GET /api/infrastructure/city/:cityId)
        │
        ▼
Area Detail → "Why this score?" → POST /api/ai/explain-area
                                    (Gemini, or offline template fallback)
        │
        ▼
Compare (2-3 areas) → POST /api/ai/compare-areas
```

**Key design decision:** the numeric investment score is *always* computed by
`services/investmentScore.service.js` on the backend, from structured inputs, using a fixed
documented weighting formula. The AI layer only ever receives the *output* of that calculation
and is prompted to explain it — it cannot invent or alter the score itself.

## Getting started

### Prerequisites

- Node.js 18+
- A MongoDB instance (local, Docker, or MongoDB Atlas free tier)
- (Optional) A Gemini API key from [Google AI Studio](https://aistudio.google.com/app/apikey)

### Install

From the project root, install both apps:

```bash
npm run install:all
```

Or install them separately:

```bash
cd server && npm install
cd ../client && npm install
```

## Environment variables

Copy the example files and fill in real values. **Never commit `.env`.**

```bash
cp .env.example server/.env
cp client/.env.example client/.env
```

`server/.env`:

```
SERVER_PORT=5000
MONGO_URI=mongodb://localhost:27017/plotwise-ai
GEMINI_API_KEY=your_gemini_api_key_here
CLIENT_URL=http://localhost:5173
```

`client/.env`:

```
VITE_API_URL=http://localhost:5000/api
```

If `GEMINI_API_KEY` is left blank, the AI endpoints automatically fall back to a deterministic,
template-based explanation built from the same structured data — the app never breaks.

## MongoDB setup

**Option A — Local MongoDB**

```bash
# macOS (Homebrew)
brew tap mongodb/brew && brew install mongodb-community
brew services start mongodb-community

# Ubuntu/Debian
sudo apt-get install -y mongodb
sudo systemctl start mongod
```

Then use `MONGO_URI=mongodb://localhost:27017/plotwise-ai`.

**Option B — MongoDB Atlas (recommended for deployment)**

1. Create a free cluster at [mongodb.com/atlas](https://www.mongodb.com/atlas).
2. Add a database user and allow your IP (or `0.0.0.0/0` for quick testing).
3. Copy the connection string into `MONGO_URI` in `server/.env`, e.g.:
   `mongodb+srv://<user>:<password>@cluster0.mongodb.net/plotwise-ai`

## Gemini API setup

1. Go to [Google AI Studio](https://aistudio.google.com/app/apikey) and create an API key.
2. Paste it into `GEMINI_API_KEY` in `server/.env`.
3. The key is **only ever used on the backend** (`server/src/services/gemini.service.js`) and is
   never sent to or exposed in the frontend.

## Seeding the database

Populates 10 Indian cities, 29 areas, and 33 infrastructure projects (all labeled as demo data):

```bash
npm run seed
```

This clears and re-seeds the `City`, `Area`, `InfrastructureProject`, and `InvestmentAnalysis`
collections, computing each area's investment score with the deterministic scoring engine.

## Running the app

From the project root (runs both server and client together):

```bash
npm run dev
```

Or separately:

```bash
# Terminal 1
cd server && npm run dev     # http://localhost:5000

# Terminal 2
cd client && npm run dev     # http://localhost:5173
```

Then open `http://localhost:5173`, search for **Bengaluru** (or any of the 10 seeded cities), and
explore.

### Production build

```bash
npm run build:client
# Serves the client/dist output with any static host; run the server with `npm start --prefix server`
```

## API documentation

Base URL: `/api`

| Method | Endpoint | Description |
|---|---|---|
| GET | `/cities` | List all cities |
| GET | `/cities/search?query=` | Search/autocomplete cities |
| GET | `/cities/:slug` | City detail + ranked areas |
| GET | `/areas/city/:cityId` | Areas for a city, with analysis |
| GET | `/areas/:id` | Single area + city + analysis + infra projects |
| GET | `/infrastructure/city/:cityId` | Infra projects for a city, grouped by type |
| GET | `/infrastructure/:id` | Single infra project |
| GET | `/analysis/city/:cityId` | All analyses for a city |
| GET | `/analysis/area/:areaId` | Analysis for one area |
| POST | `/ai/explain-area` | `{ areaId }` → AI (or fallback) explanation |
| POST | `/ai/compare-areas` | `{ areaIds: [2-3 ids] }` → AI (or fallback) comparison |
| GET | `/health` | Health check + AI-configured flag |

All responses follow `{ success, data | message }`. AI endpoints are rate-limited to 20
requests / 10 minutes per client; all other endpoints to 300 requests / 15 minutes.

## Scoring methodology

```
score = (infrastructure × 0.25) + (connectivity × 0.20) + (employment × 0.15)
      + (development × 0.15) + (demand × 0.15) + ((100 − risk) × 0.10)
score = Math.round(score)
```

Weights live in `server/src/services/investmentScore.service.js` (`SCORE_WEIGHTS`) and are
configurable in one place. See the in-app **Methodology** page for the user-facing explanation.

## Demo data mode

All seeded data is labeled `dataMode: "demo"` and every infrastructure project's `source` field
is explicitly prefixed `"Demo Dataset — ..."`. Real infrastructure authorities are referenced by
name (BMRCL, NHAI, MMRDA, HMDA, DMRC, etc. — all real organizations) for realism, but specific
project statuses/dates in the seed file are illustrative and **not** live-verified announcements.

To plug in real data later:

1. Point a scraping/import job at official sources.
2. Insert records into the same `City`, `Area`, and `InfrastructureProject` collections, setting
   `dataMode: "verified"`, a real `source`, `sourceUrl`, and `lastVerified` date.
3. No frontend or API code needs to change — the UI already renders the `dataMode`/`source`
   fields and shows a "Demo Data" badge only when `dataMode === "demo"`.

## Deployment

**Frontend (Vercel or Render static site)**
- Build command: `npm run build --prefix client` (or run inside `client/`)
- Output directory: `client/dist`
- Environment variable: `VITE_API_URL=https://<your-backend-url>/api`

**Backend (Render)**
- Root directory: `server`
- Build command: `npm install`
- Start command: `npm start`
- Environment variables: `SERVER_PORT`, `MONGO_URI`, `GEMINI_API_KEY`, `CLIENT_URL` (set to your
  deployed frontend URL for CORS)

**Database (MongoDB Atlas)**
- Create a cluster, database user, and network access rule.
- Use the Atlas connection string as `MONGO_URI` on the backend deployment.
- Run `npm run seed` once (locally, pointed at the Atlas URI, or via a one-off Render job).

## Limitations

- Demo dataset covers 10 cities and a curated set of areas/projects — not exhaustive coverage of
  India.
- Gemini explanations depend on API availability/quota; the app degrades gracefully to a
  template-based explanation rather than failing.
- No authentication/user accounts — "Saved Analysis" and recent searches are per-browser
  (`localStorage`), not synced across devices.
- Distance-based linking of infrastructure projects to areas (in the seed script) is a simple
  geographic proximity heuristic, not authoritative zoning data.
- Not tested against a live MongoDB instance in the environment this code was generated in
  (sandboxed, no network access to MongoDB's download servers) — logic was verified via Mongoose
  schema validation and a frontend production build instead. Test against your own MongoDB
  instance before relying on it.
